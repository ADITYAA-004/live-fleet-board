Project name: Live Fleet Board
Repository: https://github.com/ADITYAA-004/live-fleet-board
Project summary: A React dispatch dashboard for 30 simulated buses. A Node.js WebSocket server produces normal and burst telemetry; the browser applies per-bus sequence guards, keeps only latest state, and publishes snapshots on animation frames.

Assumptions (from DECISIONS.md):
1. The browser and server share one machine clock, and the 1,000 ms budget is measured as now minus the timestamp of the newest accepted update. With about two updates per second per bus, age naturally swings from 0 to about 500 ms. If clocks differ, skew makes displayed age misleading; if feed cadence is slower, a bus may appear stale even with an instant pipeline.
2. Each bus sequence increases within one runId, and a server restart changes runId. If wrong, the client can reject valid updates or accept an update from an earlier run.
3. The feed is simulated telemetry with the documented fields. If wrong, these tests do not validate the validity or safety of real vehicle sensors.
4. One authoritative server instance sits behind the Vite proxy. If wrong, instances can disagree about runId, sequence history, and burst responses; multi-instance coordination is not implemented.
